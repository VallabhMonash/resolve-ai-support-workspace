# Screens and interaction design

## Visual direction

A practical support dashboard: warm off-white canvas, white surfaces, dark slate text, teal primary actions, restrained borders. Typography uses the system font stack; no paid font or image dependency. Use Lucide icons with text labels on primary actions.

Desktop: 224 px navigation rail, content area, ticket detail AI panel approximately 360 px. At <= 1024 px, AI panel becomes a tab; at <= 640 px, navigation collapses and table rows become cards. Minimum supported width 360 px. Prefer clear information hierarchy over decorative charts.

Routes:
- / — product introduction, Enter demo, Manager/agent login.
- /login — workspace slug, email and password.
- /tickets — inbox and create-ticket dialog.
- /tickets/:id — ticket details, conversation/activity, AI panel.
- /knowledge — searchable article list and indexing badges.
- /knowledge/new and /knowledge/:id/edit — manager editor.
- /knowledge/:id — article reader; citation links open the specific version/passage.
- /insights — workspace facts and link to the published evaluation report.
- /evaluation — versioned static benchmark report, initially explicit Not measured.

No settings, billing or team-management page. Logout is in the navigation footer.

## Entry and demo

Lead with “Resolve support tickets with evidence.” Explain the fictional dataset in one sentence.
Enter demo has one loading state, then lands in the seeded inbox. Banner: “Demo workspace · changes expire after 24 hours.” Never imply customer data or real operational impact.
If the session/active-workspace cap is reached, show “The demo is at capacity. Please try again later.” Keep the public introduction and evaluation report accessible.

## Inbox

Toolbar: search with 300 ms debounce; status/category/priority/assignee filters; Clear filters; New ticket.
URL query parameters retain filters and page cursor. Default updatedAt descending then ID descending, 20 per page; Next/Previous supported via retained cursor stack. Reset cursors when filters change.
Rows: ticket number/title, category, priority, status, assignee, updated time. Ticket title is the navigation target.
Loading skeleton, empty inbox, no-filter-results, server error with retry are distinct states.
New ticket: title, description, category default OTHER, priority default NORMAL. Status starts OPEN; assignee optional.

## Ticket detail

Header: ticket number/title, status, priority, category, assignee. Changes save explicitly. Show conflict message with Reload latest; do not silently overwrite another update.
Main column: original description; conversation chronological; separate Activity tab; comment/reply composer.
Comment kinds INTERNAL_NOTE and REPLY have visible labels. “Save reply” stores it inside Resolve and never sends email.
Resolution is a user action. Reopening a resolved ticket is supported.

AI panel has three explicit actions:
1. Summarise & classify — summary plus proposed category/priority and short rationale. Apply suggestions is separate from generation.
2. Draft with sources — draft, citations, evidence viewer, and Edit in reply composer.
3. Find similar tickets — real tool-backed lookup, related ticket links and a short result summary.

AI action state: ready → working → result / insufficient evidence / unavailable / quota reached / failed. UI does not invent granular progress stages when the server has not reported them. Other ticket functions remain usable during inference.
Citations show article title, version and excerpt. Historical citations open their stored snapshot; archived/updated-source badges explain provenance.
Draft feedback: Helpful / Needs changes; saved once per user/run with optional note. No model “confidence percentage.”
Applying AI category/priority requires the same version check as a normal edit. A draft based on an older ticket version is marked stale before saving.

## Knowledge base

List title, updated date, published version, and status (not indexed / indexing / ready / failed / archived).
Manager editor has title, Markdown/plain text body, preview, Save version, Index, Continue indexing, Archive. Versions are immutable after save; editing creates a new version.
Saving a new version marks prior retrieval content superseded immediately. Retrieval stays unavailable for that article until current version indexing succeeds.
Index button processes one bounded batch; frontend can request the next batch while the page is open. Closing the page pauses indexing safely; Continue resumes later.
Agents see published content and source history they are permitted to access; no editing controls.

## Insights

Real DB-derived cards: open/in-progress/resolved tickets, counts by category, AI actions/successes/failures, feedback counts and median/p95 completed AI action duration for the last 7 days. Show sample count and explicit time window.
Separate owner/demo workspace data. Empty dataset shows “No runs yet,” never decorative sample metrics.
Show AI provider/model and run details only in an expandable technical details area, useful for the portfolio review.
Evaluation report uses committed measured artifacts with date, environment, model, dataset size and limitations. Before evaluation, display Not measured.

## Accessibility and browser checks

Keyboard-operable dialogs/menus; visible focus; focus restoration after modal close; labelled form errors; polite live announcements for AI completion/errors. Status never depends only on colour.
Check login/demo, filtering/navigation, ticket save/conflict, cited draft review, denied manager actions and mobile layout in Playwright. Inspect desktop 1440×900 and mobile 390×844 screenshots.
